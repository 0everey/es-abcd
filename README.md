# es-abcd

**跟 AI 一起做系统设计时，用得上的协作工具。**

装一次 → 用「工程 / 创意 / 稳定」三种说法提需求 → 得到可讨论的方案结构，并留下清单。  
不是游戏引擎，不必先装旧 ES 大框架，也不用会 PowerShell 才能理解本页。

## 它是干什么的

| 你的痛点 | 接上之后 |
|----------|----------|
| 跟 AI 聊技能/经济/道具，聊完没有结构 | 用固定场景话术，反复测同一种工作 |
| AI 容易吹成「已经验收」 | 默认只能当**设计候选**，运行时没验要明说 |
| 每个项目都要从头教 AI | 装一次，清单和入口留在项目里 |
| 怕绑死某套游戏大仓 | 任意常见工程可先分析再接入 |

**适合：** 用 AI 做系统设计、批量内容、怕翻车的扩展。  
**不适合：** 只改两行 UI；或指望一键生成可上线游戏。

## 完整使用流程

### 第 1 步 · 准备两个真实路径

- **es-abcd 根路径**：本仓库克隆后的目录  
- **项目根路径**：你的游戏/业务项目，或先建一个空文件夹当试验项目  

必须是**绝对路径**。不要说「装我电脑上」。

### 第 2 步 · 安装（二选一）

**A. 对 AI 说（推荐）**

```text
es-abcd 在 <es-abcd根路径>，装到项目 <项目根路径>，
先分析项目再按情况接入，出适配清单，用人话汇报。
```

**B. 本机一键试验**

```powershell
powershell -File .\scripts\Start-ESABCDTrial.ps1
```

脚本会新建试验目录、自动安装，并打印一段**可直接复制给 AI**的话（路径已填好）。

### 第 3 步 · 确认装上了

你应该能在项目里看到类似：

| 文件/位置 | 含义 |
|-----------|------|
| `…/out/adapt-checklist-*.md` | 适配清单：还要你拍板什么 |
| `…/out/project-profile.json` | 项目被识别成什么类型 |
| 安装/冒烟回执 | 静态自检跑过了 |

如果只有聊天记录、没有任何清单路径 → **还没装上**。

### 第 4 步 · 复制下面某一条场景发给 AI

把 `<项目根路径>` 换成你的路径，整段粘贴。  
选模式：要做对 → 工程；要发散 → 创意；要保老内容 → 稳定。

### 第 5 步 · 听人话结果

让 AI 用中文说明：

- 主推哪个方向、为什么  
- 你还要拍板什么  
- **不要**宣称已实装、已平衡、PlayMode 已过  

读法见下一节。

## 结果怎么读（人话）

| 说法 | 意思 |
|------|------|
| **通过 / 跑通了** | 这场「发散 + 选出主推荐」成功了 |
| **大约 5 个方向**（工程/稳定） | 系统给了 5 条思考主轴 |
| **大约 7 个方向**（创意） | 创意模式通常更多方案枝 |
| **主推荐主题** | 本场默认讨论焦点（如状态机、表现节拍、回滚） |
| **定一个主推荐** | 工程/稳定常见：按规则选定一个 |
| **排序推荐** | 创意常见：排了名，第一是推荐，其余仍可看 |
| **设计候选** | 只能当方案讨论，不是最终定案、不是上线批准 |
| **运行时未验** | 没在编辑器/真机验收，不能说游戏已可玩 |
| **其它方向** | 落选的是「没当第一推荐」，不是被判死刑 |

**你真正要的交付：** AI 讲清楚的方案结构 + 风险 + 待你拍板项。  
**不是：** 让你去背一串 `cand-xxxx` 编号。

## 工程模式 · 典型场景（可复制）

**什么时候用：** 技能系统、经济、道具管线、战斗闭环——要边界清楚、能落地。  
**你会感受到：** 系统偏「做对」；常见约 5 个方向，定一个主推荐（例如偏状态机、性能预算、失败恢复）。

### 场景 1 · 设计技能系统

```text
项目 <项目根路径>。用工程模式。
目标：设计一套可扩展的技能系统（主动/被动/冷却/消耗/等级）。
要求：说清模块边界、数据归谁管、和战斗结算怎么接、禁止两套技能并行。
交付：方案要点 + 风险 + 还不能宣称已实装/已平衡。
用人话讲，不要只丢英文轴名。
```

**你该得到：** 技能生命周期与模块边界、和战斗的接口、双系统禁令、风险清单。

### 场景 2 · 成长与经济

```text
项目 <项目根路径>。用工程模式。
目标：设计角色成长与货币经济（经验、金币、商店、掉落）。
要求：所有权（谁改数值）、防刷、存档边界、和任务奖励怎么统一。
交付：结构图（文字即可）+ 失败案例 + 未验证项。
用人话讲。
```

**你该得到：** 数值归谁改、防刷点、存档边界、和任务奖励如何统一。

### 场景 3 · 批量道具管线

```text
项目 <项目根路径>。用工程模式。
目标：建立「大量道具」的制作与入库管线（模板、命名、表字段、校验、批量生成）。
要求：一条正式入口、禁止手改旁路、坏数据怎么拒、和背包/掉落怎么接。
交付：管线步骤 + 验收标准 + 不能宣称已批量产完。
用人话讲。
```

**你该得到：** 从模板到入库的步骤、校验失败怎么处理、和背包/掉落的接法。

### 场景 4 · 战斗结算闭环

```text
项目 <项目根路径>。用工程模式。
目标：收口攻击→命中→伤害→死亡→复用的唯一闭环。
要求：唯一入口、禁旁路扣血、重复命中策略说清、池化重置。
交付：链路说明 + 已知缺口 + 运行时未验声明。
用人话讲。
```

**你该得到：** 唯一结算入口、禁止旁路、重复命中策略、死亡/回池注意点。

## 创意模式 · 典型场景（可复制）

**什么时候用：** 手感、日活循环、道具品类、Boss 花样——要多方案、差异大。  
**你会感受到：** 常见约 7 个方向，**排序推荐**一个；其余用来对比，不是唯一真理。

### 场景 1 · 近战技能手感发散

```text
项目 <项目根路径>。用创意模式。
目标：为「近战爆发技能」给出至少 5 种不同手感方向（节奏、风险、反制、表现挂钩）。
要求：方案之间差异要大，不要微调节流；每个方案一句话卖点 + 一个硬伤。
交付：多方案列表 + 推荐尝试顺序（非最终定案）。
用人话讲。
```

**你该得到：** 至少五种手感卡片（卖点/硬伤）+ 建议先试哪两种。

### 场景 2 · 日活玩法循环

```text
项目 <项目根路径>。用创意模式。
目标：围绕「采集—合成—战备—出击」发明 5 种日活循环变体。
要求：有的偏硬核、有的偏休闲、有的偏社交；写清吸引谁、烦谁。
交付：5 循环 + 放弃理由示例。
用人话讲。
```

**你该得到：** 五套循环差异、受众、以及为什么某套可能该放弃。

### 场景 3 · 道具品类矩阵

```text
项目 <项目根路径>。用创意模式。
目标：在不改底层背包的前提下，提出 5 套「道具品类矩阵」（消耗/装备/材料/任务/特殊）。
要求：每套有命名风格、稀有度逻辑、和战斗/经济的钩子；避免换皮。
交付：5 套矩阵要点 + 哪套最适合先做 20 个样例。
用人话讲。
```

**你该得到：** 五套品类结构 + 建议先落地的那一套。

### 场景 4 · Boss 战花样

```text
项目 <项目根路径>。用创意模式。
目标：同一 Boss 骨架，给出 5 种战法（机制向、叙事向、解谜向、配队向、Roguelike 向）。
要求：每招阶段目标不同；写清失败是否有趣。
交付：5 战法卡 + 不适合谁。
用人话讲。
```

**你该得到：** 五种打法定位、阶段目标、失败体验、不适合的玩家类型。

## 稳定模式 · 典型场景（可复制）

**什么时候用：** 老表扩展、批量导入、活动开关、修关不毁档——要贴现状、少翻车。  
**你会感受到：** 常见约 5 个方向，定一个主推荐（例如偏回滚、兼容、贴合现有集成）。

### 场景 1 · 技能表安全扩展

```text
项目 <项目根路径>。用稳定模式。
目标：在已有技能表/配置上扩展 10 个新技能，尽量不改老技能语义。
要求：兼容旧存档与旧 UI、命名不冲突、缺字段默认策略、回滚怎么做。
交付：扩展步骤 + 回归检查表 + 禁止事项。
用人话讲。
```

**你该得到：** 怎么加、怎么回归、怎么回滚、绝对不能动的老语义。

### 场景 2 · 道具批量导入

```text
项目 <项目根路径>。用稳定模式。
目标：安全导入一批道具表数据到现有项目。
要求：校验、去重、失败行隔离、部分成功策略、和现网/本地存档兼容。
交付：导入规程 + 失败样例处理 + 未测环境声明。
用人话讲。
```

**你该得到：** 导入步骤、坏行怎么隔离、部分成功怎么办。

### 场景 3 · 活动开关与配置

```text
项目 <项目根路径>。用稳定模式。
目标：为运营活动加开关与配置下发，不影响日常关卡。
要求：默认关闭安全、权限、错误配置可回退、日志可追。
交付：开关方案 + 事故预案。
用人话讲。
```

**你该得到：** 默认关、谁能开、配错如何回退、如何追查。

### 场景 4 · 老关卡修 bug 不毁档

```text
项目 <项目根路径>。用稳定模式。
目标：修复某老关卡进度卡死，不刷进度、不清档。
要求：复现条件、最小改动、兼容已卡在中途的玩家、验证步骤。
交付：修复方案 + 验证清单 + 风险。
用人话讲。
```

**你该得到：** 最小改动点、中途玩家怎么办、如何验证没毁档。

## 三种模式差在哪（已实测）

同一批 live 实测（12 场全过）里，三种模式**确实分叉**：

| 模式 | 方向数 | 选择方式 | 主推荐主题举例（人话） |
|------|--------|----------|------------------------|
| 工程 | 5 | 定一个 | 状态机完整性、性能预算、失败恢复 |
| 创意 | 7 | 排序推荐 | 表现节拍、技巧上限、心流连续 |
| 稳定 | 5 | 定一个 | 回滚、集成贴合、兼容 |

含义：

- 工程更「定结构」  
- 创意更「多枝再排」  
- 稳定更「保兼容/能回滚」  

全部仍是**设计候选**，且**运行时未验**——这是预期，不是失败。

## 边界（请先看清）

| 算成功 | 不算成功 |
|--------|----------|
| 装上了、有清单 | 游戏在编辑器里玩通了 |
| AI 给出可讨论方案 | 数值已经平衡完 |
| 三种模式能分叉测 | 可以发版上架 |
| 需要时能对上 live 证据 | 「AI 说完 = 代码已写完」 |
