# es-abcd

和 AI 用自然语言做工程决策的工具包。不依赖旧 ES 大仓，不是 Unity 插件。

**版本：** 1.0.0 正式版 · [GitHub](https://github.com/0everey/es-abcd) · [Release](https://github.com/0everey/es-abcd/releases/tag/v1.0.0) · MIT  

---

## 你先看这里（用户入口）

| 顺序 | 去哪 | 干什么 |
|------|------|--------|
| **1** | **[真实流程与结果解说](./docs/真实流程与结果解说.md)** | **中文讲清：怎么走、会得到什么、结果怎么读**（主说明） |

> **不要**一上来只钻编号回执文件。那是审计证据，不是产品说明书；先读「真实流程与结果解说」。

## 30 秒流程

```text
两个真实路径 → 安装（AI 或试验脚本）→ 看清单
        → 复制一条场景给 AI → 听人话方案
        → （可选）对照文末 live 证据
```

**安装话术：**

```text
es-abcd 在 <es-abcd根路径>，装到项目 <项目根路径>，
先分析项目再按情况接入，出适配清单，用人话汇报。
```

**本机试验：**

```powershell
powershell -File .\scripts\Start-ESABCDTrial.ps1
```

路径必须是你自己的绝对路径。

## 三种模式你会得到什么（人话）

| 模式 | 你在干什么 | 系统侧常见表现（已有 live 批） |
|------|------------|--------------------------------|
| **工程** | 把技能/经济/管线/战斗**做对** | 约 **5** 个方向，**定一个**主推荐 |
| **创意** | 要**多方案、敢分歧** | 约 **7** 个方向，**排序推荐**第一 |
| **稳定** | 老表/导入/活动/**别翻车** | 约 **5** 个方向，**定一个**偏兼容/回滚 |

**读结果时记住：**

- **通过** = 这场编排跑通了，能选出主推荐 —— **不是**游戏已可玩  
- **设计候选** = 只能当方案讨论，不是定案/上线  
- **运行时未验** = 没做编辑器/真机验收  
- 其它方向在排名里 = **落选推荐**，不是被判死刑  

完整中文解说（含三场真实例子怎么读）→ **[docs/真实流程与结果解说.md](./docs/真实流程与结果解说.md)**

## 三种模式 · 真实场景（可复制）

复制后只改 `<项目根路径>`。跑完用「结果解说」读 AI 回复；需要核对再点证据。

### 工程模式

**1. 设计技能系统**

```text
项目 <项目根路径>。用工程模式。
目标：设计一套可扩展的技能系统（主动/被动/冷却/消耗/等级）。
要求：说清模块边界、数据归谁管、和战斗结算怎么接、禁止两套技能并行。
交付：方案要点 + 风险 + 还不能宣称已实装/已平衡。
```

**2. 设计成长与经济**

```text
项目 <项目根路径>。用工程模式。
目标：设计角色成长与货币经济（经验、金币、商店、掉落）。
要求：所有权（谁改数值）、防刷、存档边界、和任务奖励怎么统一。
交付：结构图（文字即可）+ 失败案例 + 未验证项。
```

**3. 批量道具管线**

```text
项目 <项目根路径>。用工程模式。
目标：建立「大量道具」的制作与入库管线（模板、命名、表字段、校验、批量生成）。
要求：一条正式入口、禁止手改旁路、坏数据怎么拒、和背包/掉落怎么接。
交付：管线步骤 + 验收标准 + 不能宣称已批量产完。
```

**4. 任务与关卡规则**

```text
项目 <项目根路径>。用工程模式。
目标：设计任务系统与关卡胜负规则（接取、进度、失败、重试、奖励发放）。
要求：状态机清楚、断线/重进、和存档一致、禁止任务逻辑散落各处。
交付：状态与边界 + 风险清单。
```

**5. 战斗结算闭环**

```text
项目 <项目根路径>。用工程模式。
目标：收口攻击→命中→伤害→死亡→复用的唯一闭环。
要求：唯一入口、禁旁路扣血、重复命中策略说清、池化重置。
交付：链路说明 + 已知缺口 + 运行时未验声明。
```

### 创意模式

**1. 技能手感与表现发散**

```text
项目 <项目根路径>。用创意模式。
目标：为「近战爆发技能」给出至少 5 种不同手感方向（节奏、风险、反制、表现挂钩）。
要求：方案之间差异要大，不要微调节流；每个方案一句话卖点 + 一个硬伤。
交付：多方案列表 + 推荐尝试顺序（非最终定案）。
```

**2. 新玩法循环**

```text
项目 <项目根路径>。用创意模式。
目标：围绕「采集—合成—战备—出击」发明 5 种日活循环变体。
要求：有的偏硬核、有的偏休闲、有的偏社交；写清吸引谁、烦谁。
交付：5 循环 + 放弃理由示例。
```

**3. 大量道具的品类创意**

```text
项目 <项目根路径>。用创意模式。
目标：在不改底层背包的前提下，提出 5 套「道具品类矩阵」（消耗/装备/材料/任务/特殊）。
要求：每套有命名风格、稀有度逻辑、和战斗/经济的钩子；避免换皮。
交付：5 套矩阵要点 + 哪套最适合先做 20 个样例。
```

**4. Boss 战花样**

```text
项目 <项目根路径>。用创意模式。
目标：同一 Boss 骨架，给出 5 种战法（机制向、叙事向、解谜向、配队向、Roguelike 向）。
要求：每招阶段目标不同；写清失败是否有趣。
交付：5 战法卡 + 不适合谁。
```

**5. UI/信息呈现**

```text
项目 <项目根路径>。用创意模式。
目标：背包+技能盘+任务追踪，给 5 种信息架构（极简、硬核、主机、手机单手、叙事沉浸）。
要求：主次信息不同；各指出一个必踩坑。
交付：5 架构 + 首选原型建议。
```

### 稳定模式

**1. 现有技能表不翻车扩展**

```text
项目 <项目根路径>。用稳定模式。
目标：在已有技能表/配置上扩展 10 个新技能，尽量不改老技能语义。
要求：兼容旧存档与旧 UI、命名不冲突、缺字段默认策略、回滚怎么做。
交付：扩展步骤 + 回归检查表 + 禁止事项。
```

**2. 道具批量导入不炸服**

```text
项目 <项目根路径>。用稳定模式。
目标：安全导入一批道具表数据到现有项目。
要求：校验、去重、失败行隔离、部分成功策略、和现网/本地存档兼容。
交付：导入规程 + 失败样例处理 + 未测环境声明。
```

**3. 活动开关与配置热更**

```text
项目 <项目根路径>。用稳定模式。
目标：为运营活动加开关与配置下发，不影响日常关卡。
要求：默认关闭安全、权限、错误配置可回退、日志可追。
交付：开关方案 + 事故预案。
```

**4. 老关卡修 bug 不毁档**

```text
项目 <项目根路径>。用稳定模式。
目标：修复某老关卡进度卡死，不刷进度、不清档。
要求：复现条件、最小改动、兼容已卡在中途的玩家、验证步骤。
交付：修复方案 + 验证清单 + 风险。
```

**5. 性能与包体收敛**

```text
项目 <项目根路径>。用稳定模式。
目标：在现有功能不砍的前提下，收敛卡顿与包体（资源、UI、特效、表）。
要求：先度量再动刀、改动可回退、给「先做/后做」顺序。
交付：优先序 + 每项预期收益与回退方式 + 未跑性能剖析的声明。
```
