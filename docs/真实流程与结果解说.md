# 真实流程与结果解说（给使用者看）

你**不需要**先打开 `T-ENG-01.md` 那种机器回执当主页。  
那些编号报告是**文末证据**；本文讲清楚：你该怎么走、会得到什么、怎么用人话理解结果。

---

## 一、你真实该走的流程

```text
① 准备两个真实路径
   · es-abcd 装在哪（本仓库根目录）
   · 你的项目根在哪（或先用试验目录）

② 安装（二选一）
   · 对 AI 说人话安装（推荐）
   · 或本机跑试验脚本

③ 看安装产出（清单 / 画像）
   · 确认「装上了」，不是只聊了两句

④ 复制一条场景模板发给 AI
   · 工程 / 创意 / 稳定 选一种
   · 只改你的项目路径

⑤ 听 AI 用人话讲方案
   · 对照本文「结果怎么读」
   · 需要审计时再点文末证据链接
```

### ① 两个路径

必须给**绝对路径**，不要说「装我电脑上」。

### ② 怎么安装

**对 AI 说（推荐）：**

```text
es-abcd 在 <es-abcd根路径>，装到项目 <项目根路径>，
先分析项目再按情况接入，出适配清单，用人话汇报。
```

**本机一键试验（先玩再接到真项目）：**

```powershell
powershell -File .\scripts\Start-ESABCDTrial.ps1
```

装完后把脚本打印的整段话复制给 AI 即可。更细的试用说明：[开始试用.md](../开始试用.md)。

### ③ 装好后你磁盘上会出现什么

| 东西 | 人话 |
|------|------|
| 项目画像 | 系统认你是空目录 / Unity / Node 等，决定怎么装 |
| 适配清单 | 还要你拍板或补做的事项列表 |
| 安装/冒烟回执 | 证明安装与静态自检跑过了 |
| 日常入口 | 以后 AI 可在项目里调用编排能力 |

清单大致在：

`<项目根>/ES/Automation/ABCD/out/adapt-checklist-*.md`

### ④ 跑一条场景

打开仓库 [README.md](../README.md) 里「三种模式 · 真实场景」，复制一段，把 `<项目根路径>` 换成你的，发给 AI。  
例如工程·技能系统、创意·近战手感、稳定·技能表扩展。

### ⑤ 你要的「结果」是什么

不是让你去背 `cand-xxxx`。  
是让 AI 按该模式给出**可讨论的方案结构**，并且系统侧留下**可核对的选择记录**（需要时再打开证据）。

## 二、三种模式：你该期待什么

| 你选的模式 | 适合干什么 | 系统侧大致会怎样（已有 live 批） |
|------------|------------|----------------------------------|
| **工程** | 技能/经济/道具管线/战斗闭环等「做对、有边界」 | 通常给出 **5** 个方向，**确定性选一个**主推荐 |
| **创意** | 手感、循环、品类、Boss 花样等多方案发散 | 通常给出 **7** 个方向，**排序推荐**一个（不是唯一真理） |
| **稳定** | 老表扩展、导入、活动开关、修关不毁档 | 通常给出 **5** 个方向，**确定性选一个**偏兼容/回滚/贴合 |

### 人话对照表（读 AI 结果 / 读证据时用）

| 你看到的词 | 人话 |
|------------|------|
| **passed** | 这一场编排跑通了（能发散、能选出推荐），不是游戏已可玩 |
| **directionCount** | 本场提出了几条「思考方向」（工程/稳定常见 5，创意常见 7） |
| **selectedAxis** | 本场**主推荐方向的主题**（如状态机完整性、表现节拍、回滚） |
| **selectionStatus = deterministic-selected** | 按规则**定死一个**主推荐（工程/稳定常见） |
| **selectionStatus = ranked-recommended** | 排了名、**推荐第一**，其余仍可看（创意常见） |
| **claimLevel = design-candidate** | 只算**设计候选**，不是最终定案、不是上线批准 |
| **runtimeStatus = runtime-not-run** | **没跑**编辑器/真机验收；不能说 PlayMode 过了 |
| **ranked 里的其它轴** | **落选推荐**，不是「方案被判死刑」；仍可讨论 |
| **rejectedCandidatesCount = 0** | 本场没有单独的「否决名单」；主要是选优不是打官司 |

### 轴名速查（常见）

| 英文轴 | 人话 |
|--------|------|
| state-machine-integrity | 状态机/流程是否严谨 |
| ownership-lifecycle | 数据/模块归谁管、生命周期 |
| failure-recovery | 失败怎么恢复 |
| performance-peak-budget | 性能峰值与预算 |
| presentation-beat | 表现与节拍手感 |
| skill-ceiling | 技巧上限/深度 |
| flow-continuity | 心流是否连贯 |
| rollback | 能否回滚 |
| integration-fit | 是否贴现有集成 |
| compatibility | 兼容旧数据/旧行为 |

## 三、用一场真实例子读懂「结果」（证据可点）

下列数字来自仓库内已落盘的 live 报告（同一批实测），**不是手编**。

### 例子 A · 工程 · 技能系统

你对 AI 说的是「设计可扩展技能系统……」。  
系统侧一场 live 结果（摘要）：

- 状态：**通过（passed）**
- 方向数：**5**
- 主推荐主题：**状态机完整性**（`state-machine-integrity`）
- 选择方式：**确定性选中**（`deterministic-selected`）
- 级别：**设计候选**；**运行时未验**

**你该怎么用：**  
让 AI 围绕「技能状态、边界、和战斗怎么接、禁止双系统」把方案讲清楚；  
把主推荐当默认讨论焦点，其余 4 个方向当备选视角。  
**证据（审计用）：** [T-ENG-01.md](./scenario-run-reports/T-ENG-01.md)

### 例子 B · 创意 · 近战手感

- 状态：**通过**
- 方向数：**7**（比工程更多）
- 主推荐主题：**表现节拍**（`presentation-beat`）
- 选择方式：**排序推荐**（`ranked-recommended`）
- 级别：仍是**设计候选**；**运行时未验**

**你该怎么用：**  
要的是多方案差异，不是唯一答案；看排名和分差，决定试哪两个手感。  
**证据：** [T-CRE-01.md](./scenario-run-reports/T-CRE-01.md)

### 例子 C · 稳定 · 技能表扩展

- 状态：**通过**
- 方向数：**5**
- 主推荐主题：**回滚**（`rollback`）
- 选择方式：**确定性选中**
- 级别：**设计候选**；**运行时未验**

**你该怎么用：**  
讨论如何扩展技能表还不毁旧档、如何回滚；不要当成「已经导完生产数据」。  
**证据：** [T-STA-01.md](./scenario-run-reports/T-STA-01.md)

### 三模式对照（同批 12 场）

| 模式 | 场次 | 常见方向数 | 常见选择方式 | 当选主题举例（live） |
|------|------|------------|--------------|----------------------|
| 工程 | 4 场全过 | 5 | 确定性选中 | 状态机完整性、性能预算、失败恢复 |
| 创意 | 4 场全过 | 7 | 排序推荐 | 表现节拍、技巧上限、心流连续 |
| 稳定 | 4 场全过 | 5 | 确定性选中 | 回滚、集成贴合、兼容 |

完整对照表（证据）：[COMPARISON-modes-live.md](./scenario-run-reports/COMPARISON-modes-live.md)

## 四、什么叫「成功」、什么叫「还没完」

### 算成功（本工具范围内）

- 安装完成，有清单/画像  
- 按某模式跑场景，能给出主推荐方向和可讨论结构  
- 需要时能在证据里对上 directionCount / selectedAxis / claimLevel  

### 还没完（别被话术带跑）

- 游戏在 Unity 里玩通  
- 数值平衡做完  
- 可以发版上架  
- 「AI 说完 = 已经实现」

一句话：**es-abcd 强在「人和 AI 的决策结构」；玩法验收要另走编辑器/真机。**

## 五、建议你对 AI 说的收尾句

装完并跑过一条场景后：

```text
请用人话总结：你主推哪个方向、为什么、我还要拍板什么；
不要宣称已实装或 PlayMode 已过；需要时再指出证据报告编号。
```
